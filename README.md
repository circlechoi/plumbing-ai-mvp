# 배관·설비 자재 AI 인식 매칭 웹앱 (MVP 데모)

강남·서초 인테리어 시공업자를 대상으로, 배관·설비 부속(밸브, 니플, 소켓, 앵커볼트 등) 사진을 올리면
Claude Vision AI가 규격을 추정하고 호환 가능한 대체 부품을 추천해주는 데모 웹앱입니다.

결제, 실제 배차, 회원가입은 이번 MVP 범위에서 제외되었습니다. 관리자가 AI 인식 결과를 수동으로
검수/보정할 수 있는 대시보드가 포함되어 있습니다 (Wizard of Oz 방식의 안전망).

## 기술 스택

- Next.js 16 (App Router) + TypeScript + Tailwind CSS
- SQLite + Prisma ORM (`@prisma/adapter-better-sqlite3` 드라이버 어댑터 사용)
- Anthropic Claude API (Vision, `claude-haiku-4-5`) — 부품 사진 인식, `sharp`로 이미지 리사이즈 후 전송(비용 절감)

## 실행 방법

### 0. 사전 준비: Node.js

Node.js 20 이상이 필요합니다. (`node -v`로 확인)

### 1. 의존성 설치 및 DB 준비

```bash
npm install
npx prisma migrate dev   # 최초 1회: SQLite DB 생성 + 마이그레이션 적용
npx prisma db seed       # 배관/설비 부속 목업 데이터 30개 시딩
```

### 2. 환경변수 설정

`.env.example`을 참고해 `.env` 파일의 `ANTHROPIC_API_KEY`에 실제 키를 입력하세요.
(https://console.anthropic.com 에서 발급)

```bash
cp .env.example .env   # 이미 .env가 있다면 ANTHROPIC_API_KEY 값만 채워 넣으면 됩니다
```

키가 없어도 앱은 실행되지만, 사진 인식(`/api/recognize`) 시 "ANTHROPIC_API_KEY가 설정되어 있지
않습니다" 오류가 반환됩니다.

`ADMIN_PASSWORD`도 함께 설정하세요 — `/admin` 대시보드 접근에 사용되는 비밀번호입니다. 비워두면
관리자 페이지가 인증 없이 열립니다(로컬 데모 편의용 기본값이므로, 다른 사람과 공유하는 환경이라면
반드시 설정하세요).

### 3. 개발 서버 실행

```bash
npm run dev
```

[http://localhost:3000](http://localhost:3000) 에서 확인할 수 있습니다.

> **Windows에서 Node.js가 시스템 PATH에 없는 경우**: 이 프로젝트는 개발 중 관리자 권한 없이 포터블
> Node.js를 설치해 사용했습니다. 터미널에서 직접 명령어를 실행하려면 PowerShell에서 아래를 먼저
> 실행하거나, 프로젝트 루트의 `run-dev.cmd`를 더블클릭하세요.
> ```powershell
> $env:Path += ";$env:LOCALAPPDATA\Programs\nodejs-portable"
> ```

## 화면 구성

| 경로 | 설명 |
| --- | --- |
| `/` | 메인 — 사용법 안내, 부품 사진 업로드, AI 인식 결과 및 호환 대체 부품 후보 표시 |
| `/order/new` | 주문 접수 폼 (연락처, 배송지, 수량 — 입력 검증 포함) |
| `/order/[id]` | 주문 접수 완료 화면 (주문번호 복사, 다음 단계 안내) |
| `/order-lookup` | 소비자용 주문 조회 — 연락처 + 주문번호로 현재 상태 확인 |
| `/admin` | 관리자 대시보드 — 주문 목록, AI 인식 결과 확인, 수동 부품 재지정/상태 변경 (비밀번호 보호) |
| `/admin/analytics` | AI 정확도 & 비용 분석, 신뢰도 기반 자동화 온/오프 — 정확/수정됨/매칭없음 비율, 신뢰도별 정확도, 자동 처리 비율, 자주 재지정되는 부품, 실제 토큰/비용 |
| `/admin/parts` | 부품 DB 관리 — 등록된 30개 부품 목록, 새 부품/호환 정보 추가 |
| `/admin/login` | 관리자 로그인 |

## 테스트 시나리오

1. **정상 인식 플로우**: 메인(`/`)에서 니플, 소켓, 밸브류 등 배관 부속 사진을 업로드하고 "AI로
   부품 인식하기"를 누르면, 부품명·추정 규격·재질·신뢰도 배지·판단 근거가 표시됩니다. 신뢰도가
   "높음"이면 호환 부품 후보가 바로 나열되고, 각 후보 옆의 "이 부품으로 주문하기"를 누르면
   `/order/new`로 이동해 연락처/배송지/수량을 입력 후 접수할 수 있습니다.
2. **낮은 신뢰도 폴백 플로우**: 흐릿한 사진이나 배관 부속이 아닌 사진을 업로드하면 AI가 낮은
   신뢰도로 응답하도록 설계되어 있습니다 (또는 API 키 오류 시에도 동일하게 처리). 이 경우
   "정확한 매칭이 어렵습니다. 담당자가 확인 후 연락드립니다" 안내가 표시되며, 그대로 주문을
   접수할 수 있고 해당 주문은 관리자 대시보드에 "수동 확인 필요" 배지와 함께 표시됩니다.
3. **관리자 수동 보정 플로우**: `/admin`에서 접수된 주문 목록을 확인하고, "인식/지정된 부품"
   드롭다운으로 AI가 잘못 인식한 부품을 올바른 부품으로 재지정하거나 "주문 상태"를
   접수/확인중/완료로 변경할 수 있습니다. 부품을 재지정하면 "수동 확인 필요" 표시가 해제됩니다.
4. **부품 DB 확장**: `/admin/parts`에서 새 부품(부품명/규격/재질)을 추가하고, 기존 부품 중
   호환되는 항목을 체크박스로 선택해 등록할 수 있습니다.
5. **정확도/비용 분석**: 몇 건의 주문을 접수하고 그중 일부를 관리자가 재지정한 뒤,
   `/admin/analytics`에서 "정확 / 수정됨 / 매칭없음" 비율과 신뢰도별 정확도, 실제 발생한 토큰
   사용량 및 예상 비용을 확인할 수 있습니다.
6. **신뢰도 기반 자동화**: `/admin/analytics` 상단의 "자동화" 토글을 켠 뒤, 메인에서 AI 신뢰도가
   "높음"이고 호환 후보가 정확히 1개뿐인 부품 사진으로 주문을 접수해보세요. 관리자 확인 없이 주문
   상태가 바로 "확인중"으로 시작되고 "자동 처리됨" 배지가 붙습니다. 신뢰도가 중간/낮거나 후보가
   여러 개면(모호함) 자동화가 켜져 있어도 평소처럼 수동 확인 대상으로 남습니다.
7. **전체 소비자 플로우 완주**: 메인에서 사진 업로드 → (상단 진행 단계 표시가 1→2로 이동) → 인식
   결과에서 부품 선택 → 주문 폼에서 일부러 잘못된 전화번호나 빈 배송지로 제출해 인라인 에러 확인
   → 올바르게 입력 후 제출 → 접수 완료 화면에서 주문번호를 복사 → `/order-lookup`에서 방금 입력한
   연락처와 복사한 주문번호로 조회해 같은 완료 화면으로 다시 도달하는지 확인합니다.

## 배포 (Railway)

로컬 데모를 넘어 실제 URL로 공유하려면 [Railway](https://railway.com)에 배포할 수 있습니다.
Railway는 디스크가 유지되는 볼륨을 지원해서, 지금 쓰는 SQLite와 로컬 이미지 저장 방식을 거의 그대로
쓸 수 있습니다 (Vercel 같은 서버리스 환경은 재배포 시 파일이 사라지므로 별도 DB/스토리지 마이그레이션이
필요합니다).

> **비용 안내**: 신규 가입 시 30일간 쓸 수 있는 $5 크레딧을 무료로 제공합니다. 짧은 데모 목적에는
> 충분하지만, 이후에도 계속 켜두려면 Hobby 플랜($5/월)이 필요합니다.

### 1. Railway CLI 설치 및 로그인 (최초 1회, 브라우저 로그인 필요)

```bash
npm install -g @railway/cli
railway login
```

### 2. 프로젝트 생성 및 연결

```bash
cd "배관·설비 자재 AI 매칭 프로젝트 폴더"
railway init
```

### 3. 볼륨 추가 (Railway 대시보드에서)

배포된 서비스 → **Volumes** 탭 → **New Volume** → **Mount path**를 `/data`로 설정합니다.
(Railway는 서비스당 볼륨 1개만 지원하므로, DB 파일과 업로드 이미지를 모두 이 안에 둡니다.)

### 4. 환경변수 설정

```bash
railway variables set ANTHROPIC_API_KEY="실제 Claude API 키"
railway variables set ADMIN_PASSWORD="로컬과 다른 새 강력한 비밀번호"
railway variables set DATABASE_URL="file:/data/prod.db"
railway variables set UPLOADS_DIR="/data/uploads"
```

### 5. 배포

```bash
railway up
```

### 6. 최초 1회 부품 목업 데이터 시딩

```bash
railway run npm run db:seed
```

이후 `git push`나 `railway up` 재실행으로 재배포할 때마다 `npm start`가 자동으로
`prisma migrate deploy`를 먼저 실행해 DB 스키마를 최신 상태로 맞춥니다 (볼륨에 저장된 기존
주문/이미지 데이터는 유지됩니다).

### 배포 후 확인할 것

- `/api/recognize`는 호출마다 실제 Claude API 비용이 발생하므로, IP당 분당 5회로 요청을
  제한해뒀습니다 (`app/lib/rateLimit.ts`). 필요 시 한도를 조정하세요.
- 업로드된 이미지는 `/api/uploads/[filename]`을 통해 서빙됩니다 (경로 순회 공격 방지 포함).
- 로컬 `.env`의 `ADMIN_PASSWORD`("admin1234")를 그대로 배포하지 마세요 — 위 3번에서 반드시 새
  값으로 설정하세요.

## AI 인식의 한계

- 목업 부품 DB가 30개로 제한되어 있어, 등록되지 않은 특수 부품은 `matched_db_ids`가 빈 배열로
  반환됩니다 (AI가 없는 id를 지어내지 않도록 2차 검증 로직이 걸러냅니다).
- 조명이 어둡거나 부품이 잘리거나 여러 부품이 뒤섞여 있는 사진은 신뢰도가 낮게 나올 수 있습니다.
- 규격 각인이 사진에서 잘 보이지 않는 경우(예: 니플의 인치 표기가 마모됨), AI는 재질/형태만으로
  추정하므로 규격 추정이 부정확할 수 있습니다.
- 이 모든 저신뢰도 케이스는 설계상 "관리자 수동 확인"으로 안내되며, 잘못된 정보로 자동 확정되지
  않습니다.
