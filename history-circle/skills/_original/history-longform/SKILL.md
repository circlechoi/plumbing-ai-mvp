결과물: 1920x1080, 24fps, **편당 8~12분** mp4 + 유튜브 설명란 + 대본 문서.
**이 시리즈의 포인트(사용자 확정): 8~12분짜리 3부작 전투 영상으로 전략·전술의 묘미를 보여 주고, 그 내용을 시각적으로 멋지게 전달한다.**
채널 방향(편 구성 공식·세 겹 질문·라디오 기준·지도 문법)은 `history-channel-concept`을 따른다. 자매 스킬: `history-shorts`(45초 세로 쇼츠). 고증 원칙·근거 등급은 그 스킬을 따르고, 여기서는 롱폼에서 달라지는 것만 적는다. 태그는 concept 5-1 마스터 태그 표.

> **우선순위(10/23 확정)**: 스킬끼리 충돌하면 **날짜가 붙은 최신 사용자 결정**을 따른다. 날짜가 같거나 없으면 history-channel-concept > history-longform · history-architecture-shorts > history-shorts. 작업 중 낡은 문장을 발견하면 그 문장을 따르지 말고, 사용자에게 알리며 고칠 곳을 제안한다.
사용자 선호: 결론선행, 개조식(□/-/·), 출처 표기, 추정/미확인 구분, 군더더기·칭찬 없음. 결정은 선택지 2~4개 + 추천안으로 묻는다. 사용자는 말보다 **시안(이미지·영상)을 보고 판단**한다 — 큰 방향 결정 전에 저비용 시안을 먼저 만든다. 무리하거나 하지 않는 게 낫다고 보는 것은 진행 전에 질문한다.
**매번 밝힐 것: Claude는 움직임을 볼 수 없고 소리를 들을 수 없다.** 정지 프레임·음량 수치·음성 인식 결과로만 확인했다고 보고에 적고, 억양·음향 밸런스·전환 느낌은 사용자 확인을 부탁한다.

## B-0. 제작 관문 (10/23 확정)
롱폼은 세 관문을 차례로 통과한다. 관문마다 ① Claude가 산출물을 만든다(기획자·디자이너 관점, concept 0) → ② 관문에 맞는 독립 리뷰어 2~3명이 서로 모르게 검토한다 → ③ 사용자(편집장)가 고치고 승인한다. 승인 전에는 다음 관문으로 넘어가지 않는다.

| 관문 | 산출물 | 합격 기준(요약) |
|---|---|---|
| ① 비트시트 | 결정 한 문장, 세 겹 질문 표, 구간별 핵심 문장, 질문형 제목 3개 | concept 6번 점검표 1~6·10·12 |
| ② 대본 | D-1 문체 대본 + 태그 열 + 판단 분석 초고 칸(사용자 작성) | 라디오 시험(concept 3), 종결어미 분포, '것입니다' 편당 3회 이하 |
| ③ 스토리보드 | 정지 이미지 콘티 + 컷 예산(E-6) + E-5 콘티 열 | E-5 콘티 점검 6항목, E-6 반복·정지 규칙 |

- 리뷰어 3역할(10/24 사용자 결정 — 작가 추가):
  - **첫 시청자**: **그 시대 배경지식이 전혀 없는 사람(초등학생 수준)으로 설정한다**(10/25 — 온조 편 오프닝을 배경지식 없는 시청자(사용자 가족)가 '어쩌라고?'로 봄: 마한 사신·사냥·땅을 내줌이 서로 맥락 없이 들림). 처음 보는 사람이 끝까지 보나, 어디서 이탈하나, 0:30 유지율 예상, 귀로 듣기(라디오 시험 — 동음이의·화자 전환·고유명사 몰림)
  - **유튜브 디렉터**: 훅·리텐션 곡선·완급, 고리 회수(페이오프), 제목·썸네일, 강의처럼 딱딱해지는 곳. 작가가 함께 도는 관문에서는 대사 항목을 빼고 리텐션·페이오프에 집중
  - **역사영화 작가**: 장면마다 걸린 극적 질문, 대사의 맛과 말투 구분(사극 말투·번역투·현대어), 주인공의 속마음(표정 없이 행동·소품·시선·침묵으로), 내레이션이 장면의 일을 대신 설명하는 곳, 장면 전환 이음새(매치 컷·소리 다리·말 이어받기), 기억에 남을 한 줄. 조건: 사료 대사는 번역 요지에서 벗어나지 않고 새 대사를 지어내지 않는다
- 관문별 배치: ① 비트시트 = 첫 시청자 + 디렉터 / ② 대본 = 첫 시청자 + 디렉터 + 작가 / ③ 스토리보드 = 첫 시청자 + 디렉터(작가 제외). 대본을 고친 뒤 특정 역할만 다시 돌릴 수 있다(백제 1편 v1.2는 작가만, 10/24)
- 사학자 리뷰어는 두지 않는다(10/23·10/24 — '너무 딱딱해진다'). 고증은 Claude가 C 규칙과 원문 대조로 지킨다
- 리뷰어는 서로의 의견과 이전 판을 보지 않는다(Agent로 따로 띄움). 의견이 부딪히면 나란히 + 추천안 1개
- 사용자가 대본·스토리보드를 직접 고친다. Claude는 고증·문체·길이만 다듬고, 고친 곳마다 이유 한 줄
- **사용자 개입 지점(10/24 확정 — 방향성 재검토 4라운드)**: 결정 3곳 + 직접 작업 2곳만.
  - 결정 ① 비트시트 승인 / 결정 ② 대본 — Claude가 편집안까지 내고 사용자는 고칠 곳만 표시 / 결정 ③ 가편집 시청(움직임·소리, 음악 배치안 승인 포함)
  - 직접 작업 ① 판단 분석 초고 / 직접 작업 ② 판단 분석 녹음(E5)
  - 스토리보드는 Claude 컷 점검표 + 리뷰어 2명으로 처리하고, 사용자는 핵심 장면 시안 3~5장만 확인
  - 썸네일 테스트 등록·장부 캡처는 업로드 때 한 번에, 장부는 월요일 알림
- **제작 시간 기록(4라운드 실측)**: 관문마다 시작·끝 시각과 사용자 작업 시간(대략)을 기획안 문서 끝 '제작 기록' 표에 적는다. 온조 편 결과로 2주 1편 주기를 재판단한다

### D-1. 내레이션 작법 (1부에서 사용자가 승인 — 2·3부도 이대로)
**원칙: 사실을 나열하지 않고, 옆에서 설명해 주듯 잇는다.** 듣는 사람이 "왜?"를 떠올리기 전에 다음 문장이 답한다.
- **한 문단 = 한 호흡 = 한 가지 내용.** 2~3문장, 35~80자, 5~11초. 문단 하나가 음성 파일 하나
- **첫 문장은 짧게 단정, 다음 문장이 이유를 푼다.** "두 나라의 악연은 뿌리가 깊었습니다." → "…그 주몽을 없애려 했던 이가 바로, 부여의 왕자 대소였기 때문입니다."
- **연결어미로 인과를 넣는다**: ~고, ~지만, ~으니, ~다가, ~자. 마침표 단문 셋 이상 연속 금지
- **문단 사이 다리**: 하지만 / 그렇다면 / 그러니 / 다만 / 그리고 2년 뒤. 앞 문단 끝말을 다음 문단이 받는다
- **풀이 종결**: ~기 때문입니다 / ~것이었습니다 / ~셈입니다. 해석은 이 형태로. 단 **'~한 것입니다'로 문단을 맺는 것은 편당 3회 이하**(3부 초안 12회 → '딱딱하다' 피드백)
- **시제**: 사건은 현재형("돌아옵니다", "갈라집니다"), 배경·평가는 과거형
- **말 걸기**: 구간마다 한 번쯤 "이번에는 ~의 자리에 서 보겠습니다", "여러분이 왕이라면, 어떤 길을 고르시겠습니까"(2부에서 통한 장치)
- **질문으로 넘긴다**: 구간 경계와 편의 끝
- **셈을 예고하고 센다**: "답은 세 가지였습니다." → 첫째 / 둘째 / 셋째
- **기록 표지**: "~다고, 기록은 전합니다"는 [기록]에만. 사료 직접 인용 뒤 풀이 문장

### G-3. sandbox 규칙(겪은 것)

### K-2. 공통 절차
- 순서: 화면·내레이션 확정(음악 없는 원본 업로드) → 효과음 검토 → 사용자가 구간별 곡·시작·끝 지정 → 받아쓰기로 대사 시각을 찾아 최종본 기준으로 옮긴다. 사용자가 "어울리는 부분을 쓰라"고 맡기면 곡별 RMS 곡선으로 구간을 고르고 배치표를 보고한다
- **파일 받는 길**: 채팅 첨부는 sandbox로 못 보낸다 → 구글 드라이브 폴더를 '링크가 있는 모든 사용자'로 공유받아 Drive 커넥터 `search_files`(`parentId = '<폴더 id>'`)로 id → sandbox에서 `https://drive.usercontent.google.com/download?id=<id>&export=download&confirm=t`
- **승인된 음악 음량(1부)**: 곡 원본 약 -16 LUFS 기준, 일반 구간 `volume=-2dB`, 전투 `0dB`, 원음(내레이션+효과음)을 키로 `sidechaincompress=threshold=0.08:ratio=1.5:attack=150:release=900`, 마지막 `alimiter=limit=0.89`. 결과 음악 -21~-23dB, 원음 -18dB, 전체 약 -13.4 LUFS. 바람 앰비언스 때문에 문턱을 낮게 잡으면 음악이 내내 눌린다
- 2부는 효과음이 원음에 들어 있으므로 음악을 깔 때 효과음과 겹치는 구간(행군·전투)의 합산 음량을 표로 확인한다. 절정에서 현장음을 걷고 음악을 앞에 둘지는 사용자 결정(concept 4). 2부 최종: 곡마다 +2dB, 전체 −3dB, 약 −13.7 LUFS
- ffmpeg 뼈대: 곡마다 `atrim,aresample=44100,afade,volume,adelay` → `amix=normalize=0` → 감쇠 → 원음과 `amix=inputs=2:normalize=0:duration=first` → `-c:v copy -c:a aac -b:a 192k`
- 보고에는 구간별 음악·효과음·내레이션 평균 dB를 표로 주고, 들을 수 없어 수치로만 맞췄다고 적는다
