## 최우선 원칙
1. **고증이 연출보다 우선**이다. 재미를 위해 사실을 단정하거나 꾸미지 않는다.
2. **애매한 것은 애매하다고 말한다** — 대본·자막·설명란·사용자 보고 모두에서.
3. **구성은 사용자와 함께 정한다.** 크레딧을 쓰기 전 반드시 체크포인트(섹션 B)에서 확인받는다. 필요한 게 있으면 질문한다.
4. **지도를 자주 쓴다.** 시청자가 도시 위치·나라 영역·이동 경로를 파악할 수 있도록 매 편 지도 장면을 넣는다(섹션 L, v8.0 표준은 지도 v3 — L-0).
5. **채널 컨셉을 먼저 읽는다**(A-0). 우선순위는 머리말 공통 문단(최신 날짜 결정 우선).

## A-0. 채널 컨셉과의 관계 (v8.0)
- 기획·대본·제목을 시작할 때 `history-channel-concept`을 먼저 읽는다. 롱폼 내용(인물·고증·지도)은 `history-longform`이 기준
- 쇼츠의 역할 [concept 8 제안]: 쇼츠 = 질문을 던지는 곳 / 롱폼 = 답하는 곳. 재편집 편(M)은 롱폼으로 데려가는 입구, 신작은 롱폼에 없는 곁가지의 결정 또는 의외의 사실 하나
- 두 형식 병행(사용자 결정 2026-10-12): 롱폼이 나오면 재편집 3~5편 → 그 사이에 곁가지 신작. 롱폼과 내용이 겹치는 사건은 신작으로 다시 만들지 않는다
- 45초에 맞춘 컨셉 적용:
  - 한 편 = 결정(또는 의외의 사실) 하나 = 질문 하나. 편 구성 공식(딜레마 → 당신이라면? → 실제 선택 → 결과 → 남긴 것)을 압축: 훅(결말 또는 질문) → 딜레마 1~2문장(제약을 말로) → 선택 → 결과 → 시청자 질문 또는 다음 편
  - **상대를 바보로 그리지 않는다**: 상대의 계산을 한 구절이라도 그럴 만하게 세우고, 승자가 그것을 어떻게 역이용했는지로 답한다
  - **라디오 기준**: 화면에만 있는 정보를 두지 않는다(지도 라벨·연도 배지·태그도 내레이션에 나온다). "여기", "이쪽", "보시는 것처럼" 금지. 지형은 방향과 비유로 말한다
  - **신이한 기사**: "기록은 이렇게 전합니다" → "오늘의 눈으로 읽으면" 두 단계로 말해 기록과 해석을 섞지 않는다
  - **역사적 상상력**(concept 5-1): 기록이 한 줄이어도 주제를 버리지 않는다. 조건(지형·계절·정세·앞뒤 기록)으로 판단을 재구성하고 [해석]·[상상]으로 밝힌다. 기록에 없는 사건·실존 인물의 발언·숫자는 사실처럼 만들지 않는다
  - 국제 정세는 '틈'으로만 말한다(정세가 전쟁을 일으켰다고 단정하지 않음)
- **보고할 때마다 밝힌다**: Claude는 움직임을 볼 수 없고 소리를 들을 수 없다. 정지 프레임·음량 수치·받아쓰기 결과로만 확인했다고 적고, 억양·음향 밸런스·전환 느낌은 사용자 확인을 부탁한다
- 작업 관점: 기획·대본·컷을 볼 때 concept 0의 두 역할(유튜브 기획자 / 영상 디자이너)로 차례로 검토하고 보고를 두 이름으로 나눠 적는다

## A. 곁가지 후보 발굴 도구: '이야기 사슬' (v8.1)
채널 구조는 concept 8-1의 시즌(시대순, 나라별 가닥 → 충돌)이다. 이 절은 그 시즌 롱폼의 앞뒤 사건에서 **곁가지 신작 후보**를 찾는 방법이다. 하나의 사건(앵커)에서 시청자가 가질 법한 궁금증을 ◀●▶ 방향으로 훑어 후보를 내고, 사용자가 고른다.

### A-1. 다음 편으로 가는 3가지 방향
| 방향 | 질문 예 | 연도 배지 |
|---|---|---|
| ◀ 과거로(원인·배경) | 왜 고구려를 떠났을까? 한강엔 원래 누가 살았을까? | '약 BC 1세기' |
| ● 옆으로(동시대·장소·증거) | 왜 하필 한강이었을까? 위례성은 어디였을까? | '기록상 BC 18' |
| ▶ 앞으로(다음 사건·결과) | 그 뒤 백제는 어떻게 커졌을까? | '약 4세기' |
- 방향 기호(◀●▶)는 편성표·기획용이다. 화면 연도 배지에는 v7.4부터 ◀▶를 쓰지 않는다(D-3).
- 매 편 끝에 다음 후보를 방향별로 1개씩(최대 3개) 제시하고 사용자가 고른다. 댓글 반응도 참고.
- 질문은 **실제 시청자가 물을 말투**로("왜 하필 한강이야?").

### A-2. 파생 질문 발굴 틀 (앵커마다 훑어보고 후보를 사용자에게 제시)
장소(왜 여기?) / 원인(왜 일어났나?) / 사람(누가 있었나?) / 주변(이웃·경쟁은?) / 증거(어떻게 아나?) / 결과(그래서 어떻게 됐나?)
- **뻔함 필터(v7.5, 2026-10-01 사용자 판단 "너무 뻔한 주제")**: 교과서·드라마로 널리 알려진 이야기(예: ⑥ 부러진 칼)는 피드에서 넘겨진다. 후보마다 ① 의외의 주인공·원인(사람이 아닌 눈·돼지, 어린아이) ② 충격적 결정 ③ 처음 듣는 기록 중 하나 이상을 갖췄는지 표시하고, 없으면 같은 사건을 다른 질문으로 비튼다(예: '대소의 인질 요구' → '부여는 왜 고구려를 바로 없애지 못했을까?'). 제목·첫 문장은 인물을 아는 사람만 궁금한 "왜 ~했을까?"보다 **의외의 사실 + 물음**으로.
- 답이 사료로 뒷받침되지 않고 추측만 남는 질문은 후보에 올릴 때 '답이 애매함'을 표시한다. 그런 편은 '아무도 모른다'를 주제로 삼는 편(미스터리 편)으로 만들 수 있다.

### A-5. 장기 서사 아크 (사용자 결정, 2026-09-29 · 순서 변경 2026-10-04 — 완료된 아크, 기록용)
- (v8.0) 롱폼 진행 상황·구성·인물은 history-longform 0·A가 기준이다. 아래는 쇼츠 쪽 기록.
- **순서 변경(사용자 결정 2026-10-04)**: 숏폼은 ⑤~⑨로 '심기'를 마친 것으로 보고 **롱폼 3부작을 먼저 제작**한다. 아래 표의 ⑩·⑪은 숏폼으로 먼저 내지 않으며, 숏폼은 롱폼이 나온 뒤 그 내용으로 이어간다(A-4).
- **목표**: 고구려 건국 이야기를 숏폼으로 쌓은 뒤(⑤~⑨ 완료), **대무신왕의 부여 전쟁**을 롱폼 3부작(편당 8~10분, 16:9)으로 만든다. 내용은 임용한 교수 강의를 참고(해석은 '해설자 견해'로 출처 구분, 강의 화면·음성은 쓰지 않음), 구성과 미학은 Kings and Generals 참고(전황 지도 → 삽화 전투 → 다시 지도의 반복, 부대 이동 화살표, 극적인 다큐 내레이션).
- **중심 갈등**: 부여 맏왕자(훗날 왕) **대소** ↔ 주몽 → 유리 → **무휼(대무신왕)**. 3대에 걸친 원한이 롱폼에서 결판난다.
- **숏폼이 롱폼을 위해 심어야 할 것**:
  | 편 | 심는 것 |
  |---|---|
  | ⑤ | 대소 = 주몽을 없애려던 자, 부여를 등진 무리 + 졸본 세력의 결합 |
  | ⑥ | '부여에서 온 왕자' 유리(아이러니: 그 부여가 고구려를 괴롭힘) |
  | ⑦ | 대소의 첫 공격(인질 요구 → 침공 → 큰 눈으로 퇴각) — 고구려는 아직 약자 |
  | ⑧ | 주인공 무휼 등장(알을 쌓는 비유의 대답) |
  | ⑨ | 굽힐 것인가 맞설 것인가 — 유리왕의 저자세 외교와 형 해명의 죽음(무휼이 물려받을 숙제) |
  | ⑩(보류 — 롱폼 먼저) | 전술가 무휼의 첫 승리(학반령 매복) → 롱폼 1부에서 다룸 |
  | ⑪(보류 — 롱폼 먼저) | 전쟁 전야의 상징(머리 하나 몸 둘 붉은 까마귀) → 롱폼에서 다룸 |
- **반복 상징**: 부러진 칼(유리), 쌓아 올린 알(무휼), 붉은 까마귀(전조). 숏폼에서 한 번씩 보여 주고 롱폼에서 다시 불러낸다(붉은 까마귀는 롱폼에서 처음 등장).
- **긴장 곡선**: 협박 → 침공 → 역습 → 전야 → 전면전. 각 숏폼은 다음 도발을 예고하며 끝낸다.
- 세부 연도(유리왕 14·28·32년, 대무신왕 3~5년)는 제작 전에 한국 고대 사료 DB로 재확인한다(2026-09-29 기준 일부는 기억 기반).
- 롱폼 제작 시 새로 필요한 것: 16:9 렌더, 지도 위 부대 표식 이동·충돌 애니메이션, 삽화 레이어 분리(패럴랙스), 장 구분, 긴 BGM 설계.

## B. 공동 구성 체크포인트 (크레딧 쓰기 전 필수)
사용자가 있을 때는 `AskUserQuestion`(없으면 텍스트)으로 확인한다. 한 번에 1~3개만 묻는다.
1. **편 선정**: 편성표 + 다음 후보(◀●▶) 제시 → 사용자 선택(자유 입력 허용)
2. **고증 시트 확인**(섹션 C): 특히 학설이 갈리는 항목은 "어느 설을 중심으로, 나머지는 언급만?" 또는 "여러 설을 나란히 소개?"를 묻는다
3. **대본·장면 구성 확인**: 내레이션 전문 + 8~9장면 한 줄 설명(지도 장면 포함) + 지도 미리보기 이미지 + 예상 크레딧 → 승인 후에만 이미지·음성 생성
4. **완성본 확인**: 영상 전달 후 수정 요청 반영(해당 장면/음성만 재생성)
- 사용자가 "알아서 해줘"라고 한 단계는 합리적 선택을 하고 그 선택을 보고에 밝힌다.
- 사용자 도메인 지식이나 선호(어느 사료 중심, 감정 톤, 특정 인물 강조 등)가 필요하면 질문한다.
- **대본은 사용자와 주고받으며 고친다(v7.6, ⑨)**: 사용자가 직접 쓴 대본이나 다른 AI가 만든 초안·이미지를 가져오면 ① 기준(훅/흐름/고증/분량/핵심 메시지)을 먼저 밝히고 평가 ② 고증 오류·비문·오해를 부르는 표현만 고치고 **사용자 문장과 말투는 그대로 살린다** ③ 고친 곳마다 이유를 한 줄씩. ⑨ 최종 대본은 사용자가 쓴 8문장이었고, 고친 것은 '칼로 목숨을 끊은→칼을 받고'(실제 죽음은 창), '적국→이웃 나라', '서신→말' 정도
- 사용자가 방향만 주면(예: "외교 이슈를 부각", "이런 해설도 버무리자") 고증 등급을 붙여 반영안을 내고, 근거가 약한 해설은 [해석]으로만 싣는다(C-2)
- **재편집 편(M)은 체크포인트를 줄인다**: ① 편 수·구간·화면 배치·끝 문구(AskUserQuestion, 배치 목업 1장) ② 완성본 확인. 내용 고증은 롱폼에서 끝났으므로 다시 하지 않고, 설명란에 롱폼의 고지를 옮긴다

## C. 고증 프로토콜 (가장 중요)
### C-1. 조사
- WebSearch/WebFetch로 조사. 우선 출처: 국사편찬위원회(한국사데이터베이스·우리역사넷), 한국민족문화대백과사전, 국립중앙박물관·지역 국립박물관, 국가유산포털, 학술논문(KCI). 블로그·나무위키는 단서로만 쓰고 근거로 쓰지 않는다.
- 한국사데이터베이스(db.history.go.kr/id/...)와 한국민족문화대백과(encykorea.aks.ac.kr/Article/...)는 WebFetch로 읽힌다. 우리역사넷(contents.history.go.kr)은 robots 차단으로 읽히지 않음.
- 핵심 사실 하나당 가능하면 독립 출처 2곳 이상으로 확인.
- 읽지 못한 페이지(차단·오류)는 그 사실을 사용자에게 알리고, 그 페이지에 기대는 주장은 '미확인'으로 둔다.
- (v8.0, 롱폼에서) 위키문헌·한국사DB·우리역사넷은 WebFetch에서 막힐 때가 많고, WebFetch 요약기는 원문 전문 인용을 거부한다 → 짧은 사실 확인 질문으로 묻거나, 앱 안 브라우저를 쓰거나, 사용자에게 원문을 붙여 달라고 한다

### C-2. 근거 등급 (모든 문장에 부여)
- (v8.1) 태그의 뜻·전체 목록은 concept 5-1 마스터 태그 표가 원본이다. 쇼츠는 [기록][통설][추정][여러 설][미상][해석][상상][연출]을 쓴다. 아래 표의 '내레이션 표현'은 쇼츠용 보조 기준이며, 문체는 D-2 v8.1 기본 문체를 따른다
| 등급 | 의미 | 내레이션 표현 | 자막 태그 |
|---|---|---|---|
| 기록 | 사료에 그렇게 적혀 있음(사실 여부와 별개) | '『○○』에 따르면 ~했다' | (없음) |
| 통설 | 학계 다수가 받아들이는 해석 | '~라고 보는 학자가 많다' | [통설] |
| 추정 | 학계가 '추정'으로만 제시(반대 설은 못 찾았지만 확정 아님) | '~로 짐작한다' | [추정] |
| 여러 설 | 학계 의견이 갈림 | '~했다고도, ~했다고도 전한다' | [여러 설] |
| 미상 | 알 수 없음 | '이건 아무도 모른다' | [미상] |
- 내레이션 표현은 v7.4 다큐체 기준. v7 이야기꾼체('~단다', '~지')는 D-2 참고.
- [추정] 등급은 사용자 결정(2026-09-27)으로 추가. 예: 부아악 = 북한산 인수봉 부근(한국사데이터베이스 주석).
- **[해석] 태그(v7.6, ⑨)**: 사료가 사실만 적고 의미는 말하지 않는데 영상이 의미를 덧붙일 때(예: '활 선물 = 복종 요구', '외교 마찰') 쓴다. 학계 서술로 확인되면 [통설]/[추정], 확인되지 않은 해설(위키 각주·블로그·강의)은 [해석]. 내레이션은 단정하지 않고 '~라는 듯', '~로 읽힌다', '~셈'으로, 자막 1줄 앞에 `[해석]`, 설명란 첫 항목에 "기록이 아닌 해석"이라고 밝힌다
- 신화·전설은 '기록'이라도 사실처럼 말하지 않는다('~라고 전한다').
- 사료 간 기록·학설이 갈리면 **기본값은 '주류 설 중심으로 영상 진행, 나머지 설은 설명란'**(사용자 결정, 2026-09-27). 단, 핵심 주장 자체가 불확실하면 영상 안에서도 짧게 '확실하지 않다'고 말한다. 편에 따라 사용자가 달리 원하면 그에 따른다.
- 연도는 '기록상 연도'인지 '추정 연대'인지 구분한다(배지에 '기록상 BC 18', '약 BC 1세기' 등).
- **태그를 롱폼과 맞춤(v8.0)**: [기록]·[통설]·[추정]·[여러 설]·[미상]·[해석]에 더해 **[상상]**(concept 5-1 절차로 조건을 재구성한 판단 — 내레이션에서 경계를 말한다: "기록은 여기까지입니다. 여기서부터는 그날의 조건으로 재구성한 이야기입니다.") / **[연출]**(가상 인물·대사·복식 색 등 화면의 연출 — 설명란 고지). 내레이터 문장은 [기록]·[통설] + 원리를 설명하는 [해석]까지, 기록에 적힌 것처럼 말하지 않는다
- **고정 사실(v8.0, 롱폼 고증)**: 국내 천도 서기 3년(유리왕 22년) / 1세기 초 고구려는 동해에 닿지 않는다 — 동옥저 복속은 태조대왕 4년(56년) '東至滄海', 그 전 동해안은 옥저, 영동 일대는 낙랑 동부도위 [통설] / 국내성 [통설] 지안 / 졸본 [통설] 환런 / 부여 중심 [여러 설]. 인과 주장·시대 소급 금지는 D-0 그대로

### C-3. 고증 시트 (체크포인트 2에서 사용자에게 제시)
- 사건/질문, 관련 1차 사료(가능하면 원문 구절 병기), 연도(기록상/추정)
- 핵심 사실 3~6개: 각각 등급(C-2) + 출처
- 이설·논쟁 지점과 처리 방안 제안
- 시각 고증: 복식(재질·색·장식), 머리모양, 건축(움집/목책/토성/기와), 무기, 깃발·문양 — 각각 근거 또는 '미확인'
  - **확인되지 않은 국가 문양·깃발 문장은 만들지 않는다** → 무늬 없는 천 깃발 또는 깃발 없음
  - 시대가 이를수록 소박하게(삼베·무명, 무채색). 비단·금관 등은 유물·사료로 확인된 시기·신분에만
  - 복식·건축 자료가 거의 없는 시기는 인물을 원경·실루엣으로 처리해 디테일 단정을 피한다
- AI 이미지는 고증이 완벽하지 않음을 전제로, 생성 후 이미지를 보고(가능하면 Read로 확인) 시대에 맞지 않는 요소(화려한 옷, 문양, 후대 건축)를 사용자에게 보고한다. 이미지를 직접 볼 수 없으면(작업공간은 Higgsfield CDN 차단) 그 사실을 밝히고 사용자 확인을 요청한다.
- 최종 영상 하단에 '이미지는 AI 재현' 문구를 출처와 함께 표기한다.
- **지도 고증**(L-2): 표시할 도시·유적의 비정 위치와 등급, 영역 경계의 근거(어느 문헌/지도 기준인지)를 시트에 적는다.

## D. 대본 설계 — 45초 신작 (약 43초)
### D-0. 서사 점검표 (v7.3, 대본을 사용자에게 보이기 전에 반드시 통과)
2026-09-29 교훈: ⑤ 초안이 '3세기 5부'와 '기원전 1세기 유리 태자 책봉'을 "실마리는 여기!"로 억지 연결했고, 사용자가 개연성을 지적함. 또 2~4번 문장이 사실 나열이라 흐름이 끊김.
1. **핵심 메시지 한 문장**을 먼저 쓴다(예: "부여를 등진 주몽 무리가 졸본 세력과 손잡아 고구려를 세웠고, 부여의 대소는 적이 된다"). 모든 문장은 이 메시지를 밀어야 한다. 밀지 않는 사실은 설명란으로.
2. **문장 간 연결 테스트**: 이웃한 두 문장 사이에 '그래서 / 그런데 / 그러자 / 한편' 중 하나를 넣어 말이 되는지 확인. 어느 것도 안 들어가면 순서를 바꾸거나 연결 문장을 넣는다.
3. **인과 주장 검증**: "A 때문에 B" "실마리는 A"처럼 원인을 말하는 문장은 사료나 학계 서술이 그 인과를 직접 말하는지 확인. 아니면 인과 표현을 빼고 사실만 나란히 두거나 [추정]으로.
4. **시대 소급 금지**: 근거 사료의 시점과 사건 시점을 나란히 적어 본다. 수십 년 이상 차이 나면 '훗날'로만 연결하고 원인으로 쓰지 않는다.
5. **대립·인물 축 확인**: A-5 아크에서 이번 편이 심어야 할 인물·갈등이 들어갔는지(예: ⑤는 대소).
6. **예고 약속 확인**: 마지막 질문을 다음 편이 실제로 사료로 답할 수 있는지. 답이 기록에 없으면 '미스터리 편'이라고 사용자에게 알린다.
7. 점검 결과(핵심 메시지 문장 + 각 문장의 역할 한 단어: 훅/배경/갈등/전환/근거/반전/예고)를 대본과 함께 사용자에게 보여 준다.

### D-1. 기본 구조 (10비트 + 연출 기본값) — 사용자와 합의해 변형 가능. v7.5부터 비트를 8~9장면으로 묶는다(예: 2+3, 9+10)
| # | 역할 | 대략 시간 | 연출 기본값(move / trans) |
|---|---|---|---|
| 1 | 훅: 이번 편 질문(또는 사건) — 화면 상단 타이틀 | 0~4.5s | 움직이는 컷(`video`) 또는 `punch` / 첫 장면(타이틀 슬램 + 북 소리) |
| 2 | 이전 편 연결 또는 갈등 제시 | ~9s | `in` / `ink` |
| 3 | 배경/전개 | ~13.5s | `pan_l`·`pan_r` / `ink`·`whip_*` |
| 4 | 전개 또는 단서 1 | ~18s | 지도 `focus`(경로·영역) / `ink` |
| 5 | 전개 또는 단서 2 | ~22s | `in` / 무음 `cut` |
| 6 | 핵심(답 또는 절정) | ~27s | `punch` / `cut`(타격음) + 펀치 자막 |
| 7 | 근거와 확실성 수준(기록/통설/추정/여러 설/미상) | ~31s | 지도 `focus` 또는 `out`+`mist` / `ink` |
| 8 | 한 단계 더(의외의 사실 또는 반대 설) | ~36s | `in` / `flash` |
| 9 | 새 궁금증(◀●▶ 중 합의한 방향) | ~40s | `in` / 무음 `cut` + 펀치 자막 |
| 10 | 다음 편 예고 | ~45s | `in` / `ink` |
- 실제 장면 전환 시각은 내레이션 받아쓰기로 문장 시작에 맞춘다(H 참고).
- **첫 장면(v7.3)**: 지도가 아니라 가장 강렬한 장면(인물·긴장) + 상단 제목(4~5어절, `{핵심어}` 금색). 내레이션 첫 문장은 곧바로 이번 편 질문. "자, 옛날 옛적" 같은 도입은 쓰지 않는다(스와이프 방어, 2026-09-29 사용자 결정). 지도는 2번째 장면 이후. ⑤부터 첫 장면은 움직이는 컷(F-4). **v7.6**: 첫 문장은 질문 대신 **결말을 먼저 던지는 한 문장**도 된다(⑨ "아버지가 보낸 칼을 받고 스스로 목숨을 끊은 고구려 태자, 해명."). 사용자가 "약하다"고 한 훅: 원인과 결과를 한 문장에 다 설명하는 문장("선물로 받은 활을 꺾었다가, 아버지에게 칼을 받은 태자가 있습니다")
- **시그니처 3초 축약판(v8.0, 사용자 결정 2026-10-12)**: 신작 첫 장면은 수묵화 스틸 → 먹물 한 방울이 번져 화면을 덮음 → 같은 구도의 움직이는 실사 컷, 모두 약 3초 안. 그 뒤 본편은 청록산수. 채널이 수묵화에서 시작했다는 정체성(concept 7-2)을 쇼츠에도 새기되 훅이 늦어지지 않게 ① 제목은 0.15초부터(지금처럼) ② 첫 내레이션(질문 또는 결말 한 문장)도 0초부터 ③ 실사 컷은 가장 강한 액션 순간(아래 '첫 장면 구도' 규칙). 만드는 법 F-5. 실사는 이 3초에만 쓰고 본편 그림체는 바꾸지 않는다. [미검증 — 첫 적용 편에서 시안으로 길이·먹 번짐 속도·톤 차이를 사용자에게 확인]

## G. 렌더링 (Higgsfield `sandbox_exec`에서만)
- 작업공간(Bash)은 Higgsfield CDN·업로드 주소 접근이 403 → 다운로드·합성·업로드는 모두 sandbox_exec에서. 작업공간은 **코드 미리보기용**(GitHub raw·PyPI는 됨).
- sandbox 사양(2026-09-28 확인): 8코어, 메모리 7GB, Python 3 + Pillow 12.3 + numpy 2.4 + faster-whisper, ffmpeg 5.1. 명령 1회 최대 16,000자.
- **sandbox 유지**: 호출이 끝나고 약 10초 뒤 폐기되지만, `background:true` 작업이 도는 동안은 15분 임대가 유지된다. 첫 호출을 '다운로드 + sleep 840' 백그라운드로 띄워 두고, 15분이 지나기 전에 같은 방식으로 다시 띄운다.
- **스크립트 전달**: render.py(**v7.6, 29,510바이트, md5 197958161508814c8e813be3cb66864c**)가 16,000자를 넘으므로 sandbox에 `rA.py`·`rB.py`로 따로 쓴 뒤 `cat rA.py rB.py > render.py`(파트 A 13,525바이트, 파트 B 15,985바이트·15,207자 — 16,000자 한도에 가까우니 같은 명령에 다른 내용을 붙이지 않는다). `sprite.py`(4,099바이트)는 **항상** 같은 폴더에 따로 쓴다(v8.1 도트 필수 — 없으면 렌더러가 조용히 건너뛰므로 H에서 확인). 각각 `md5sum`으로 확인. 스크립트를 base64로 옮기지 않는다(Higgsfield 도구 지침).
- 영상 컷 프레임은 uint8 배열(5초 약 0.9GB)로 두고 톤 보정은 ffmpeg 필터에서 한다(numpy float 변환은 메모리 3GB를 써서 작업공간에서 OOM이 났음).
- 렌더를 중간에 멈출 때 `pkill -f render.py`를 쓰면 그 명령을 실행한 셸까지 죽는다 → `pkill -f 'python3 render'`처럼 쓴다.
- 긴 명령이 API 502로 끊겨도 sandbox 안에서는 실행됐을 수 있다 → 파일 존재부터 확인하고, 업로드 PUT이 412면 이미 올라간 것(If-None-Match).
- 실측: 45초 렌더 약 100초(8코어), 받아쓰기 약 30초, 지도 검수(qa.py) 약 60초. 결과 파일 약 70MB.
- **메모리 초과(v7.6, ⑨에서 2회 실패)**: `pool.imap`으로 전 프레임을 한꺼번에 넘기면 인코딩이 밀릴 때 주 프로세스에 프레임(장당 6.2MB)이 쌓여 3.9GB에서 OOM으로 죽었다(`dmesg | grep -i oom`, 배경 작업 로그에 'Killed'). → 48프레임 묶음(`pool.map`)으로 수정. 그래도 렌더 중 사용 메모리가 6GB 안팎까지 오르므로 렌더 중에는 다른 무거운 작업을 띄우지 않는다
- **업로드 전 검증(v7.6)**: 렌더가 죽으면 깨진 final.mp4가 남고, 그대로 PUT하면 200이 떨어져 그 업로드 주소를 못 쓰게 된다. `ffprobe … > probe.txt && grep -q "^4" probe.txt && curl … PUT`처럼 길이가 정상일 때만 올린다. 깨진 파일이 올라갔으면 `media_confirm`하지 말고 `media_upload`로 새 주소를 받는다
- **(v8.0) 롱폼 작업에서 겪은 sandbox 규칙**: foreground 호출이 약 60초를 넘으면 502 → 오래 걸리는 건 background로 돌리고 `sleep ≤58`로 폴링. 502 난 작업이 뒤에서 계속 돌 수 있으니 pid로 중복 확인 후 kill / `pkill -f <자기 명령 문자열>`은 자기 셸을 죽인다 → pid로 kill / 디스크 약 26GB — 영상 raw 캐시는 작업 사이에 지운다 / 병렬 curl은 잘린다 → 순차 받기 + 재시도, PNG는 PIL로 load 검사 / 업로드 주소는 한 번만 쓸 수 있고 1GB 넘는 파일은 400·502 / 몽타주 정책 오류가 나면 접촉 시트는 PIL로 직접 만든다
- 수정본 재렌더(자막·지도·서체만 바꿈)는 크레딧 0, 약 2분. sandbox가 살아 있으면(`ls ~/hs`) 파일을 다시 올리지 않고 scenes.json·spec만 고쳐 다시 돌린다

- 고정 댓글: 번호나 한 단어로 답할 수 있는 질문 **하나만**(영상 마지막 논점을 그대로 — 예: `여러분이 유리왕이었다면? 1⃣ 일단 굴복하고 힘을 기른다 2⃣ 무휼처럼 맞선다`, ⑨ `여러분이 유리왕이었다면? 1⃣ 나라가 먼저다, 칼을 보낸다 2⃣ 아들을 살린다`). 영상이 시청자 질문으로 끝난 편은 그 질문을 그대로 쓰고 다음 편 예고 문장은 붙이지 않는다. 다음 편 투표형(`다음엔 어떤 게 궁금해? ① {후보1} ② {후보2}`)과 번갈아 쓴다
- 재생목록: 앵커(사건)별 1개, 편 번호순
- 해시태그: #한국사 #{국가/왕조} #{인물} #역사서클 #shorts
- 아동용: 아니요 / 공개범위: 비공개 업로드 → 확인 후 공개
- '변경되거나 합성된 콘텐츠' 공개 항목 표시 권장
- 배경음악: 효과음·앰비언스는 렌더에 포함(합성음). BGM은 ① 음원 파일이 있으면 scenes.json `bgm`으로 렌더 단계에서 덕킹해 섞고(권장, 편마다 음량 일정), ② 없으면 업로드 후 YouTube 라이브러리 음원을 붙인다. YouTube 오디오 보관함 곡은 곡마다 저작자 표시 조건이 다르므로 설명란 표기 여부를 확인한다.

## L. 지도
### L-0. 지도 v3 (v8.0 채널 표준 — 사용자 결정 2026-10-12, 롱폼과 통일)
- 원칙(롱폼 E-3과 같음): 지형·위치는 코드, 그림체는 지형 음영, 세력 면·글자·화살표·표지는 코드
- **국경은 지형을 따른다**: 롱폼 지도 키트(키트 zip의 mapkit/: `tiles.py` terrarium 고도 타일 → `style.py` 지형 음영 → `bake3.py` 세력 면 → `sA.py`·`sO.py` 장면 JSON). bake3는 나라별 대략 다각형을 씨앗으로 두고 비용 = 고도 + 강 + 노이즈로 skimage watershed → 국경이 산줄기·큰 강을 따른다. 중립 씨앗으로 빈 땅을 남기고, 면 음영 `sh = 1 + 0.7*(lum - mu)`로 지형이 비친다. 직선·다각형·톱니 국경 금지
- **세력 색(진한 저채도)**: 고구려 (96,34,29) / 부여 (42,58,86) / 신(新)·낙랑 (70,74,22) / 흉노·선비·옥저·삼한은 bake3 표 그대로. 영동 낙랑 동부도위는 `xin_e`로 따로 둔다(삼한 색이 북으로 번지지 않게). 백제·신라·가야 색은 처음 나오는 편에서 정하고 시리즈 안에서 바꾸지 않는다
- **영역은 그 시점 기록으로**: 1세기 초 고구려는 동해에 닿지 않는다(옥저가 사이에 — C-2 고정 사실). 근거를 고증 시트에 적는다
- 표시: 지도 장면은 다크 톤. 부여 화살표 흰 붓선 [234,230,220], 고구려 붉은 붓선 [204,36,34]. 국명은 지도 위 큰 글자, 지명·거점 핵심 표지는 붉은 원 표지(anim.json markers — 10/19). 인장('§', 한자 숫자는 글꼴에 없음)은 이름표에만 쓰고, 선택지·작전 설명에는 쓰지 않는다(롱폼 E-6). 모든 라벨은 내레이션에도 나온다(A-0)
- 세 단계 줌(concept 7-1): 전략도 → 작전도 → 전술도. 45초 신작은 보통 한 단계만 쓰고, 줌으로 범위가 바뀌면 내레이션에서도 말한다
- **세로 적용 [미검증 — 첫 적용 편에서 시안 1장으로 확정]**: 키트는 16:9 기준이다. ① bake3 결과를 같은 투영으로 9:16 범위(세로 위도 폭 기준)로 다시 굽거나 ② 넓게 구운 결과에서 세로로 잘라 쓴다. 이 배경을 scenes.json 지도 장면 `image`로, 표지·경로·라벨은 L-3 spec → anim.py로 올린다. anim.py는 경위도 선형(cos(lat) 보정) 투영이므로 bake3 배경도 같은 center·span_lat·투영이어야 표지가 제자리에 온다 — 투영이 다르면 배경을 anim.py 투영으로 다시 샘플링한다. 제목(y 300~470)·자막 띠(1130~1610)를 피해 핵심 표지를 y 600~1100에
- 재편집 편(M)은 롱폼의 지도 컷을 박스 모드로 그대로 쓴다
- **이전 방식(L-1~L-7: AI 재채색 korea_full + 붉은 표지)은 대체용**으로 남긴다 — 나라 영역 없이 도시 위치·이동 경로만 보일 때, 또는 v3 세로 판이 준비되기 전. 나라 영역을 보일 때는 v3

### (대체용) 채색 지도 (v7: 코드 밑그림 + AI 재채색 + 코드 표지)
**원칙**: 지형(해안선·강·산지 위치)은 코드가, 그림체는 AI가, 표지·경로·글자는 다시 코드가 맡는다. AI에게 지도를 처음부터 그리게 하지 않는다(해안선이 틀어짐). **사용자가 승인한 한반도 지도(L-5의 korea_full)의 그림체를 채널 표준으로 고정**하고, 새 지도는 항상 그 지도를 두 번째 참조 이미지로 넣어 그림체를 맞춘다(사용자 결정, 2026-09-28).

### L-1. 언제 쓰나
- 전체 조망: 이야기의 무대가 한반도 어디인지(도읍·주요 도시 표시)
- 이동: 인물·집단의 이동, 천도, 원정 경로(점선 화살표)
- 영역: 나라·세력의 대략적 범위와 그 변화(근거 있을 때만)
- 방위 설명: 사료가 동서남북을 말할 때 방향 라벨만 달고 구체 지명은 단정하지 않는다
- 근거: 유적 위치(예: 풍납토성)를 확대해 표시

### L-2. 지도 고증 규칙
- 도시·유적 위치는 비정(比定) 근거가 있는 곳만 찍고 부제에 등급을 단다: `[통설] 서울 풍납토성`, `[추정] 북한산 인수봉 부근`, `[여러 설] 인천 또는 아산`. `[미상]`이거나 `[여러 설]`이 넓게 갈리면 점을 찍지 않고 '?' 라벨·개념 경로만(예: ⑤ 부여).
- **위치 미상인 나라를 그래도 보여 줘야 할 때(v7.6, ⑨ 사용자 결정 — 점선 원이 아니라 '지도에 색칠하듯 영역으로')**: 점·경계선 없이 **번지는 색칠 영역 + `이름 ?` 글자**(`regions`, `alpha` 0.5)로 '이 근처 어딘가'만 전한다. 위치·크기는 화면 배치상의 임의 선택임을 note("○○은 위치 미상(임의 표시)")와 설명란에 밝힌다. 다른 표지·경로·제목과 겹치지 않는 쪽에 둔다(⑨ 황룡국: 졸본 서쪽)
- 확인된 좌표(현대 위치): 풍납토성 127.117E 37.528N / 미추홀(인천 일대, 통설) 126.67E 37.44N / 부아악(추정) 126.99E 37.66N / 졸본=환런 오녀산성(통설, 위키백과 근거라 공식 DB 재확인 필요) 125.417E 41.328N / 석촌동 고분군(근사) 127.104E 37.502N / 국내성=지안 일대(통설, 근사 좌표·재확인 필요) 126.18E 41.12N
- 부여 도읍: 통설은 지린시 동단산·남성자 일대(경향신문 보도 기준)이나, 대소의 부여(동부여 포함) 위치는 [여러 설] → ⑤에서는 점 없이 북쪽 '?'에서 내려오는 개념 경로만
- 영역(regions)은 근거 문헌·교과서·백과사전 지도에서 확인한 범위만. 근거를 못 찾으면 영역을 그리지 않고 도시 점만 쓴다(예외: 바로 위 '위치 미상' 표시 — 반드시 `?`와 임의 표시 고지를 붙인다).
- 현대 국경선은 그리지 않는다(AI 프롬프트에도 금지). 현대 지명은 부제에만('지금의 ○○').
- 해안선·강은 **현대 기준**이고 **산 표현은 과장**이다. note와 설명란에 밝힌다. 개념적인 경로는 '경로는 개념도'.
- 핵심 표지·경로는 줌이 끝난 화면 기준 y 500~1100 안에 오게 center/span_lat/zoom/focus를 잡는다. note는 화면 고정 문구(y 550, 오른쪽 정렬).

### L-3. spec 형식 (ep/m_이름.json) — anim.py 입력
```json
{"out":"maps/m_korea.png","center":[126.4,38.8],"span_lat":15.2,"zoom":1.5,
 "markers":[{"name":"위례성","sub":"[통설] 서울 풍납토성","lon":127.117,"lat":37.528,"main":true,"side":"r","at":2.4}],
 "routes":[{"pts":[[125.42,41.15],[126.2,39.6],[127.02,37.66]],"label":"남쪽으로","at":0.8,"dur":1.5}],
 "regions":[{"name":"…","poly":[[lon,lat],…],"color":[150,70,40],"label_at":[lon,lat],"size":76,"alpha":0.3,"at":0.2,"dur":1.3}],
 "labels":[{"text":"?","lon":126.75,"lat":39.55,"size":170,"color":[170,38,32]}],
 "note":"위치는 통설 기준 · 경로는 개념도 · 현대 해안선"}
```
- **center/span_lat은 배경으로 쓸 AI 지도의 밑그림(ctl.py spec)과 반드시 같아야** 표지가 제자리에 온다. L-5 라이브러리의 값을 그대로 복사한다.
- center=[경도,위도], span_lat=화면 세로 위도 폭(한반도+요동 약 15.2, 지역 확대 약 3, 도성 주변 약 0.6). side: r/l/u/d. `at`·`dur`: 장면 시작 후 등장 시각·그려지는 시간. route `color` 기본은 붉은색, 개념 경로는 회갈색 [110,100,90].
- ⑤ 예시(korea_full 재사용, 부여→졸본 개념 경로): `{"out":"maps/m_ep5.png","center":[126.4,38.8],"span_lat":15.2,"zoom":1.55,"markers":[{"name":"졸본","sub":"[통설] 환런 오녀산성 일대","lon":125.417,"lat":41.328,"main":true,"side":"r","at":0.2}],"routes":[{"pts":[[126.6,43.7],[126.1,42.6],[125.55,41.55]],"color":[110,100,90],"at":0.5,"dur":1.6}],"labels":[{"text":"?","lon":126.75,"lat":43.95,"size":130,"color":[170,38,32]}],"note":"부여 위치는 여러 설 · 경로는 개념도"}`
- ⑧ 예시(부여→국내성, 나머지는 ⑤와 같음): marker `{"name":"국내성","sub":"[통설] 지안 일대","lon":126.18,"lat":41.12,"main":true,"side":"r","at":0.2}`, route pts `[[126.6,43.7],[126.45,42.5],[126.25,41.35]]`
- ⑨ 예시(국내성·졸본 + 황룡국 영역, 제목에 안 가리게 초점을 북쪽으로): `{"out":"maps/m_ep9.png","center":[126.4,38.8],"span_lat":15.2,"zoom":1.45,"focus":[125.5,42.5],"markers":[{"name":"국내성","sub":"[통설] 지안 일대","lon":126.18,"lat":41.12,"main":true,"side":"r","at":0.2},{"name":"졸본","sub":"[통설] 환런","lon":125.417,"lat":41.328,"side":"d","at":0.9}],"routes":[{"pts":[[126.6,43.7],[126.45,42.5],[126.25,41.35]],"color":[110,100,90],"at":0.5,"dur":1.6}],"regions":[{"name":"황룡국 ?","poly":[[123.9,41.3],[124.2,42.0],[124.8,42.2],[125.15,41.85],[125.1,41.4],[124.7,41.0],[124.2,40.95]],"color":[196,140,20],"label_at":[124.55,41.55],"size":70,"alpha":0.5,"at":1.6,"dur":1.2}],"labels":[{"text":"부여 ?","lon":127.35,"lat":42.9,"size":100,"color":[170,38,32]}],"note":"황룡국은 위치 미상(임의 표시) · 부여는 여러 설 · 경로는 개념도"}`
- 가까운 표지 둘(졸본·국내성)은 글자 방향을 다르게(`side` d / r), 부제는 짧게 — 길면 옆 표지와 겹친다. 줌이 끝난 화면에서 라벨이 제목(y 300~470)·note(y 550) 뒤로 가지 않게 `focus`·`zoom`을 조절하고 PREVIEW로 확인한다

### L-4. 새 지도 만들기 (라이브러리에 같은 범위가 없을 때)
1. 밑그림: `{"center":[경도,위도],"span_lat":폭,"blur":4}`로 ctl.py 실행 → `ctl_이름.png`(1152x2048, 해안선·강·고지 갈색, 글자 없음) + `ctl_이름_land.png`(검수용). 산이 조각나 보이면 `blur` 10
2. `media_upload`(png) → sandbox에서 PUT → `media_confirm(type:image)`
3. `get_cost`로 비용 확인(high 2k 2.75) 후 `generate_image`/`generate_image_batch`: `model gpt_image_2_5`, `quality high`, `resolution 2k`, `aspect_ratio 9:16`, `medias: [{value: 밑그림 media_id, role: image_references}, {value: 0cf3c69c-be10-429f-be94-719b2d8b5f5a, role: image_references}]`(두 번째 = 표준 그림체)
4. 검수: `python3 qa.py ai.png ctl_land.png overlay.jpg` → 해안선 ±40px 일치율·IoU·최적 이동. 기준: IoU ≥ 0.88이고 최적 이동이 (0,0,1.0) 근처. 참고로 정확한 코드 지도의 IoU도 0.905가 상한(분류기 한계). 바다가 5% 미만인 지도는 수치 무의미 → 사용자 눈 확인
5. 통과하면 겹침본(overlay.jpg)을 업로드해 사용자에게 링크로 보여 주고, L-5 라이브러리에 추가

**좁은 범위(span_lat < 2) 하천 지도(v7.1)**: Natural Earth 1:10m 하천 선은 도시 규모에서 수 km 어긋난다(한강·송파 일대 약 2km). 서울 한강은 `han_mask.py`(통계청 행정동 경계 — 한강 양안 구 경계 = 중심선, 폭 1km)로 하천 면을 만들고 ctl spec에 `"water_mask":"kr/han_mask.png","ne_rivers":false`. 재채색 프롬프트는 "STRICTLY PRESERVE the exact course, position, bends and width of the blue river band … do not widen it" 문구 사용. #!/usr/bin/env python3
"""AI 재채색용 밑그림(control map): 정확한 해안선·강·고지(갈색)만, 글자 없음. + 검수용 육지 마스크.
사용: python3 ctl.py spec.json out_prefix   → out_prefix.png(1152x2048), out_prefix_land.png"""
import json, math, sys, os
import numpy as np
from PIL import Image, ImageDraw, ImageFilter
W, H = 1152, 2048
DATA = os.environ.get('MAPDATA', 'mapdata'); REL = os.environ.get('RELIEF', 'relief')
def geo(n): return json.load(open(os.path.join(DATA, n + '.geojson')))['features']
def polys(g): return [g['coordinates']] if g['type'] == 'Polygon' else (g['coordinates'] if g['type'] == 'MultiPolygon' else [])
def lines(g): return [g['coordinates']] if g['type'] == 'LineString' else (g['coordinates'] if g['type'] == 'MultiLineString' else [])
def crop(path, a, b, c, d):
    im = Image.open(path).convert('RGB'); iw, ih = im.size
    return im.resize((W, H), Image.BICUBIC, box=((a + 180) / 360 * iw, (90 - d) / 180 * ih, (b + 180) / 360 * iw, (90 - c) / 180 * ih))
S = json.load(open(sys.argv[1])); pre = sys.argv[2]
cx, cy = S['center']; span = S['span_lat']; k = math.cos(math.radians(cy)); ppd = H / span
P = lambda lo, la: (W / 2 + (lo - cx) * k * ppd, H / 2 - (la - cy) * ppd)
lh, th = (W / 2) / (k * ppd), span / 2
inv = lambda pts, m=1.5: any(cx - lh - m < p[0] < cx + lh + m and cy - th - m < p[1] < cy + th + m for p in pts)
lm = Image.new('L', (W, H), 0); d = ImageDraw.Draw(lm); rings = []
for f in geo('ne_10m_land'):
    for p in polys(f['geometry']):
        if not inv(p[0]): continue
        pts = [P(*q[:2]) for q in p[0]]; d.polygon(pts, fill=255); rings.append(pts)
        for hole in p[1:]: d.polygon([P(*q[:2]) for q in hole], fill=0)
lm.save(pre + '_land.png')
e = np.asarray(crop(os.path.join(REL, 'etopo1.jpg'), cx - lh, cx + lh, cy - th, cy + th), np.float32) / 255
mx = e.max(-1); gr = (e[..., 1] >= e[..., 0])            # 초록 계열 = 저지
elev = np.where(gr, 0.1, np.clip((0.86 - mx) / 0.5, 0, 1) * .8 + .2)
elev = np.asarray(Image.fromarray((elev * 255).astype(np.uint8)).filter(ImageFilter.GaussianBlur(S.get('blur', 4))), np.float32) / 255
sh = np.asarray(crop(os.path.join(REL, 'shadedrelief.jpg'), cx - lh, cx + lh, cy - th, cy + th).convert('L').filter(ImageFilter.GaussianBlur(2)), np.float32) / 255
low, high = np.array([150, 190, 120], np.float32), np.array([150, 105, 60], np.float32)
land = low + (high - low) * np.clip((elev - .2) / .7, 0, 1)[..., None]
land = land * (0.8 + 0.5 * (sh - sh.mean()))[..., None]
sea = np.array([96, 150, 196], np.float32)
m = np.asarray(lm, np.float32)[..., None] / 255
img = Image.fromarray(np.clip(land * m + sea * (1 - m), 0, 255).astype(np.uint8))
d = ImageDraw.Draw(img)
for pts in rings: d.line(pts + [pts[0]], fill=(40, 40, 40), width=2)
if S.get('water_mask'):  # v7.1: 정밀 하천 면(han_mask.py 등)을 물로 칠함 — 좁은 범위에서 Natural Earth 선은 수 km 어긋남
    wm = Image.open(S['water_mask']).convert('L').resize((W, H))
    img.paste((30, 110, 220), (0, 0), wm); d = ImageDraw.Draw(img)
    img.paste((20, 60, 120), (0, 0), Image.eval(wm.filter(ImageFilter.FIND_EDGES), lambda v: 255 if v > 60 else 0))
if S.get('ne_rivers', True):
    for f in geo('ne_10m_rivers_lake_centerlines'):
        for l in lines(f['geometry']):
            if inv(l, .5): d.line([P(*q[:2]) for q in l], fill=(30, 110, 220), width=6, joint='curve')
img.save(pre + '.png'); print('saved', pre)
```

#!/usr/bin/env python3
"""AI 재채색 지도 검수: 해안선 일치도(IoU) + 이동·배율 탐색 + 원본 해안선 겹쳐 그린 확인용 이미지.
사용: python3 qa.py ai.png ctl_land.png overlay.png"""
import sys, json
import numpy as np
from PIL import Image, ImageFilter, ImageChops
W, H = 1152, 2048
ai = Image.open(sys.argv[1]).convert('RGB').resize((W, H), Image.LANCZOS)
land = np.asarray(Image.open(sys.argv[2]).convert('L'), np.float32) > 127
a = np.asarray(ai.filter(ImageFilter.GaussianBlur(3)), np.float32)
# 해안에서 먼 확실한 바다/육지 픽셀로 각 4개 색 중심을 학습 → 전체를 가까운 쪽으로 분류(그림체가 바뀌어도 동작)
L8 = Image.fromarray(land.astype(np.uint8) * 255)
deep_land = np.asarray(L8.filter(ImageFilter.MinFilter(61)), np.uint8) > 127
deep_sea = np.asarray(L8.filter(ImageFilter.MaxFilter(61)), np.uint8) < 128
def km(X, k=4, it=12):
    c = X[np.random.default_rng(0).choice(len(X), k, replace=False)]
    for _ in range(it):
        lab = ((X[:, None] - c[None]) ** 2).sum(-1).argmin(1)
        c = np.array([X[lab == j].mean(0) if (lab == j).any() else c[j] for j in range(k)])
    return c
px = a.reshape(-1, 3); rs = np.random.default_rng(1)
cl_ = km(px[rs.choice(np.flatnonzero(deep_land.ravel()), 4000)]); cs_ = km(px[rs.choice(np.flatnonzero(deep_sea.ravel()), 4000)])
dl = ((px[:, None] - cl_[None]) ** 2).sum(-1).min(1); ds = ((px[:, None] - cs_[None]) ** 2).sum(-1).min(1)
sea_ai = (ds < dl).reshape(H, W)
sea_ai = np.asarray(Image.fromarray(sea_ai.astype(np.uint8) * 255).filter(ImageFilter.ModeFilter(9)), np.uint8) > 127
band = np.asarray(L8.filter(ImageFilter.MaxFilter(81)), np.uint8) > 127
band &= np.asarray(L8.filter(ImageFilter.MinFilter(81)), np.uint8) < 128      # 해안선 ±40px 띠
m = np.zeros((H, W), bool); m[int(H * .05):int(H * .95), int(W * .06):int(W * .94)] = True   # 분홍 번짐 가장자리 제외
def iou(dx, dy, s):
    im = Image.fromarray((~sea_ai).astype(np.uint8) * 255)
    im = im.transform((W, H), Image.AFFINE, (1 / s, 0, W / 2 - (W / 2 + dx) / s, 0, 1 / s, H / 2 - (H / 2 + dy) / s), Image.NEAREST)
    x = np.asarray(im) > 127
    i = (x & land & m).sum(); u = ((x | land) & m).sum(); return i / max(u, 1)
base = iou(0, 0, 1.0)
best = max(((iou(dx, dy, s), dx, dy, s) for s in (0.97, 1.0, 1.03) for dx in range(-40, 41, 20) for dy in range(-40, 41, 20)))
# 확인용: AI 그림 위에 실제 해안선(빨강) 겹치기
edge = Image.fromarray(land.astype(np.uint8) * 255).filter(ImageFilter.FIND_EDGES).filter(ImageFilter.MaxFilter(3))
ov = ai.copy(); ov.paste((220, 30, 30), (0, 0), edge)
ov.save(sys.argv[3], quality=90) if sys.argv[3].endswith('.jpg') else ov.save(sys.argv[3])
coast_acc = float(((~sea_ai) == land)[band & m].mean())
print(json.dumps({'coast_band_accuracy': round(coast_acc, 3), 'iou_as_is': round(float(base), 3), 'best': [round(float(best[0]), 3), best[1], best[2], best[3]],
                  'sea_ratio_ai': round(float((sea_ai & m).mean() / m.mean()), 3), 'sea_ratio_true': round(float((~land & m).mean() / m.mean()), 3)}))
```

#!/usr/bin/env python3
"""AI 지도 위에 올릴 애니메이션 정보만 계산: spec.json -> <out>.anim.json (+영역 레이어). 배경은 AI 재채색 지도를 쓴다.
spec의 center/span_lat은 그 AI 지도를 만든 밑그림(ctl.py)과 같아야 좌표가 맞는다."""
import json, math, sys
from PIL import Image, ImageDraw, ImageFilter, ImageChops
W, H = 2160, 3840
for sp in sys.argv[1:]:
    S = json.load(open(sp)); cx, cy = S['center']; span = S['span_lat']
    k = math.cos(math.radians(cy)); ppd = H / span
    P = lambda lon, lat: (W / 2 + (lon - cx) * k * ppd, H / 2 - (lat - cy) * ppd)
    out = S['out']; A = {'regions': [], 'routes': [], 'markers': [], 'note': S.get('note', ''), 'zoom': S.get('zoom', 1.5)}
    if S.get('regions'):
        layer = Image.new('RGBA', (W, H), (0, 0, 0, 0))
        for r in S['regions']:
            c = tuple(r.get('color', [150, 60, 40])); pts = [P(*p) for p in r['poly']]
            pm = Image.new('L', (W, H), 0); ImageDraw.Draw(pm).polygon(pts, fill=255); pm = pm.filter(ImageFilter.GaussianBlur(18))
            edge = ImageChops.subtract(pm, pm.filter(ImageFilter.MinFilter(15)))
            a = ImageChops.lighter(pm.point(lambda v, _a=r.get('alpha', .30): int(v * _a)), edge.point(lambda v: min(255, int(v * 1.6))))  # v7.6: 영역 농도 alpha
            layer = Image.alpha_composite(layer, Image.merge('RGBA', [Image.new('L', (W, H), v) for v in c] + [a]))
            lx, ly = P(*r['label_at']) if r.get('label_at') else (sum(p[0] for p in pts) / len(pts), sum(p[1] for p in pts) / len(pts))
            A['regions'].append({'name': r['name'], 'xy': [lx, ly], 'color': list(c), 'size': r.get('size', 76), 'at': r.get('at', .2), 'dur': r.get('dur', 1.3)})
        lp = out.replace('.png', '.layer.png'); layer.save(lp); A['layer'] = lp
    t = .5
    for rt in S.get('routes', []):
        at = rt.get('at', t); dur = rt.get('dur', 1.6); t = at + dur + .2
        A['routes'].append({'pts': [list(P(*p)) for p in rt['pts']], 'color': rt.get('color', [178, 34, 30]), 'label': rt.get('label', ''), 'at': at, 'dur': dur})
    ms = sorted(S.get('markers', []), key=lambda m: not m.get('main')); t = t if S.get('routes') else .4
    for i, m in enumerate(ms):
        A['markers'].append({'xy': list(P(m['lon'], m['lat'])), 'name': m['name'], 'sub': m.get('sub', ''), 'side': m.get('side', 'r'),
                             'main': bool(m.get('main')), 'at': m.get('at', t + .3 * i)})
    A['labels'] = [{'xy': list(P(l['lon'], l['lat'])), 'text': l['text'], 'size': l.get('size', 50), 'color': l.get('color', [40, 80, 105])} for l in S.get('labels', [])]
    f = S.get('focus')
    A['focus'] = [v / s for v, s in zip(P(*f) if f else (A['markers'][0]['xy'] if A['markers'] else (W / 2, H / 2)), (W, H))]
    json.dump(A, open(out.replace('.png', '.anim.json'), 'w'), ensure_ascii=False); print('anim', out)

#!/usr/bin/env python3
"""AI 재채색 지도 하천 보정(v7.1): 정밀 하천 마스크 기준으로
① 마스크 밖으로 번진 물 → 주변 땅색으로 메움  ② 마스크 안인데 땅으로 칠해진 곳 → 주변 물색으로 메움  ③ 바뀐 강둑에 옅은 먹선.
사용: python3 fix_river.py ai.png river_mask.png out.png [허용폭_px(1152폭 기준, 기본 4)]"""
import sys
import numpy as np
from PIL import Image, ImageFilter
ai = Image.open(sys.argv[1]).convert('RGB'); W, H = ai.size
tol = float(sys.argv[4]) if len(sys.argv) > 4 else 4
rv = Image.open(sys.argv[2]).convert('L').resize((W, H), Image.BILINEAR)
t = int(tol * W / 1152) * 2 + 1
M = lambda x: Image.fromarray(x.astype(np.uint8) * 255)
dil = lambda x, n: np.asarray(M(x).filter(ImageFilter.MaxFilter(n)), np.uint8) > 127
ero = lambda x, n: np.asarray(M(x).filter(ImageFilter.MinFilter(n)), np.uint8) > 127
river = np.asarray(rv, np.uint8) > 127
a = np.asarray(ai, np.float32); sm = np.asarray(ai.filter(ImageFilter.GaussianBlur(3)), np.float32)
r, g, b = sm[..., 0], sm[..., 1], sm[..., 2]
wat = (b > r + 30) & (b > g - 10)
tex = a - np.asarray(ai.filter(ImageFilter.GaussianBlur(4)), np.float32)            # 붓결·종이 결
def fill_from(src):  # 정규화 합성곱: src 픽셀 색으로 가까운 곳부터 채움
    fill = np.zeros_like(a); done = np.zeros((H, W), bool); w = src.astype(np.float32)
    for sig in (6, 14, 30, 60, 120):
        den = np.asarray(Image.fromarray((w * 255).astype(np.uint8)).filter(ImageFilter.GaussianBlur(sig)), np.float32) / 255
        num = np.stack([np.asarray(Image.fromarray(np.clip(a[..., c] * w, 0, 255).astype(np.uint8)).filter(ImageFilter.GaussianBlur(sig)), np.float32) for c in range(3)], -1)
        ok = (den > .12) & ~done
        fill[ok] = (num / np.maximum(den, 1e-3)[..., None])[ok]; done |= ok
    fill[~done] = a[~done]
    return fill
# ① 넘친 물 → 땅
too_wet = wat & ~dil(river, t)
too_wet = dil(too_wet, 7) & ~dil(river, max(3, t - 4))
land_fill = fill_from(~dil(wat, 9)) + np.roll(tex, 80, 1) * .6
# ② 빠진 물 → 물
too_dry = ero(river, 5) & ~wat
too_dry = dil(too_dry, 5) & river
water_fill = fill_from(ero(wat, 5) & river) + np.roll(tex, 40, 0) * .4
feather = lambda x: np.asarray(M(x).filter(ImageFilter.GaussianBlur(2.5)), np.float32)[..., None] / 255
m1, m2 = feather(too_wet), feather(too_dry)
out = a * (1 - m1) + land_fill * m1
out = out * (1 - m2) + water_fill * m2
# ③ 바뀐 곳의 새 강둑에 옅은 먹선
final_w = (wat & ~too_wet) | too_dry
bank = dil(final_w, 3) & ~ero(final_w, 3) & dil(too_wet | too_dry, 9)
e = np.asarray(M(bank).filter(ImageFilter.GaussianBlur(1.2)), np.float32)[..., None] / 255 * .5
out = out * (1 - e) + np.array([50, 80, 90], np.float32) * e
Image.fromarray(np.clip(out, 0, 255).astype(np.uint8)).save(sys.argv[3])
print(f'water {int(wat.sum())} px · 넘친 물 제거 {int(too_wet.sum())} · 빠진 물 채움 {int(too_dry.sum())}')

### L-7. 대체용: 코드로 그리는 채색 지도 (map.py v7)
AI 재채색이 검수를 통과하지 못하거나 크레딧을 아낄 때 쓴다. 고도 기반 채색 + 과장된 산 그림 + 굵은 강. 산 그림은 장식이며 좁은 범위(span_lat < 2)는 고도 자료가 거칠어 산을 생략한다. 결과 PNG를 `image`로, 같은 폴더의 `.anim.json`을 `map`으로 쓴다.

#!/usr/bin/env python3
"""채색 산수 지도 렌더러 v7: spec.json -> 배경 PNG(2160x3840) + 영역 레이어 + 애니메이션 JSON.
v7: 고도(ETOPO1 색 음영도에서 추정) 기반 청록·황토 채색 + 음영 + 과장된 산 그림 + 굵은 물길 + 수채 바다.
영역·경로·표지·note는 render.py가 시간에 맞춰 그린다(원본 좌표계에 그려서 줌해도 글자가 떨리지 않음)."""
import json, math, sys, os, random

def lowfreq(w, h, cells, seed):
    r = np.random.default_rng(seed).random((cells[1], cells[0])).astype(np.float32)
    return np.asarray(Image.fromarray((r * 255).astype(np.uint8)).resize((w, h), Image.BICUBIC), np.float32) / 255

def crop_eq(path, lon0, lon1, lat0, lat1):

    im = Image.open(path).convert('RGB'); iw, ih = im.size
    box = ((lon0 + 180) / 360 * iw, (90 - lat1) / 180 * ih, (lon1 + 180) / 360 * iw, (90 - lat0) / 180 * ih)
    return im.resize((W, H), Image.BICUBIC, box=box)

def elevation(rgb):
    """ETOPO1 색(초록=저지 → 황갈=중간 → 짙은 갈색=고지)에서 0~1 고도 지수 추정."""
    a = np.asarray(rgb, np.float32) / 255; r, g, b = a[..., 0], a[..., 1], a[..., 2]
    mx, mn = a.max(-1), a.min(-1); v = mx; d = mx - mn + 1e-6
    h = np.where(mx == r, ((g - b) / d) % 6, np.where(mx == g, (b - r) / d + 2, (r - g) / d + 4)) * 60
    tan = np.clip((0.86 - v) / 0.5, 0, 1) * 0.75 + 0.25
    green = np.clip((0.62 - v) / 0.5, 0, 0.15)
    return np.where(h < 75, tan, green).astype(np.float32)

def palette(e):
    out = np.zeros(e.shape + (3,), np.float32)
    xs = [s[0] for s in LAND_STOPS]
    for c in range(3): out[..., c] = np.interp(e, xs, [s[1][c] for s in LAND_STOPS])
    return out

def mountain_img(h, rng, lit, shade):
    """수묵 채색 산 한 덩이(RGBA): 부드럽게 들쭉날쭉한 능선, 왼쪽 위 빛, 바위 주름결, 청록 산자락, 먹 능선, 아래는 번지듯 사라짐."""
    w = h * rng.uniform(1.25, 1.8); ww, hh = int(w) + 10, int(h) + 10
    n = int(rng.integers(9, 15)); kx = np.linspace(0, w, n)
    env = np.clip(np.sin(np.pi * kx / w), 0, 1) ** .7
    jag = rng.uniform(.45, 1.0, n); jag[int(rng.integers(n // 3, 2 * n // 3 + 1))] = 1.0
    ky = env * jag * h; ky[0] = ky[-1] = 0
    X = np.arange(ww, dtype=np.float32) - 5
    hp = np.interp(X, kx, ky)
    hp = np.convolve(hp, np.ones(5) / 5, 'same') + (np.random.default_rng(int(rng.integers(1e9))).random(ww) - .5) * h * .015
    hp = np.clip(hp, 0, None)
    Y = np.arange(hh, dtype=np.float32)[:, None]; top = hh - 5 - hp[None, :]
    depth = (Y - top) / max(8., h)                       # 능선 0 → 아래로 증가
    slope = np.gradient(np.convolve(hp, np.ones(9) / 9, 'same'))
    litf = np.tanh(slope * 1.6) * .5 + .5
    g = np.random.default_rng(int(rng.integers(1e9)))
    furrow = np.asarray(Image.fromarray((g.random((max(2, hh // 18), max(2, ww // 4))) * 255).astype(np.uint8)).resize((ww, hh), Image.BICUBIC), np.float32) / 255
    lit_c, sh_c = np.array(lit, np.float32), np.array(shade, np.float32)
    col = sh_c + (lit_c - sh_c) * np.clip(litf[None, :] + (furrow - .5) * .5, 0, 1)[..., None]
    col = col * (1 - .22 * np.clip(depth, 0, 1))[..., None]
    rim = np.exp(-np.clip(depth, 0, None) * h / 4)[..., None] * litf[None, :, None] * .35
    col = col + (255 - col) * rim                          # 빛 받는 능선 가장자리 밝게
    foot = np.clip((depth - .35) / .45, 0, 1)[..., None] * .7
    col = col * (1 - foot) + np.array([92, 142, 110], np.float32) * foot
    alpha = (depth >= 0) * np.clip(1 - (depth - .85) / .3, 0, 1) * 240
    im = Image.fromarray(np.dstack([np.clip(col, 0, 255), alpha[..., None]]).astype(np.uint8), 'RGBA')
    d = ImageDraw.Draw(im, 'RGBA'); ridge = [(float(x) + 5, hh - 5 - float(y)) for x, y in zip(X - 5 + 5, hp)][::3]
    d.line(ridge, fill=INK + (190,), width=max(2, int(h / 45)), joint='curve')
    pk = [j for j in range(1, n - 1) if ky[j] >= ky[j - 1] and ky[j] >= ky[j + 1]]
    for j in pk:
        x0, y0 = kx[j] + 5, hh - 5 - ky[j]
        for q in range(int(1 + h / 55)):
            L = h * rng.uniform(.12, .32) * (ky[j] / h); dx = rng.uniform(.05, .35) * L
            d.line([(x0 + dx * .2, y0 + 3), (x0 + dx * .6, y0 + L * .6), (x0 + dx, y0 + L)], fill=INK + (95,), width=max(1, int(h / 75)))
    return im

        g = mountain_img(h, rng, lit, shade)

    img.paste(layer.filter(ImageFilter.GaussianBlur(.8)), (0, 0), layer.filter(ImageFilter.GaussianBlur(.8)))

    d = ImageDraw.Draw(img, 'RGBA')

    riv += [[P(*p) for p in rv['pts']] for rv in S.get('rivers_extra', [])]

            lx, ly = P(*r['label_at']) if r.get('label_at') else (sum(p[0] for p in pts) / len(pts), sum(p[1] for p in pts) / len(pts))
            A['regions'].append({'name': r['name'], 'xy': [lx, ly], 'color': list(c), 'size': r.get('size', 76),
                                 'at': r.get('at', 0.2), 'dur': r.get('dur', 1.3)})
        lp = out.replace('.png', '.layer.png'); layer.save(lp); A['layer'] = lp
    t = 0.5
    for rt in S.get('routes', []):
        at = rt.get('at', t); dur = rt.get('dur', 1.6); t = at + dur + 0.2
        A['routes'].append({'pts': [list(P(*p)) for p in rt['pts']], 'color': rt.get('color', [178, 34, 30]),
                            'label': rt.get('label', ''), 'at': at, 'dur': dur})
    ms = sorted(S.get('markers', []), key=lambda m: not m.get('main'))
    t = t if S.get('routes') else 0.4
    for i, m in enumerate(ms):

        A['markers'].append({'xy': [x, y], 'name': m['name'], 'sub': m.get('sub', ''), 'side': m.get('side', 'r'),
                             'main': bool(m.get('main')), 'at': m.get('at', t + 0.3 * i)})
    f = S.get('focus')
    A['focus'] = [v / s for v, s in zip(P(*f) if f else (A['markers'][0]['xy'] if A['markers'] else (W / 2, H / 2)), (W, H))]
    json.dump(A, open(out.replace('.png', '.anim.json'), 'w'), ensure_ascii=False)
    print('saved', out, 'mountains', len(mts))
